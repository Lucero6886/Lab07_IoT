2. Tổng quan Lab

Tên chuẩn hóa: Thiết lập Cơ sở Dữ liệu Đám mây Phi quan hệ (NoSQL) để Quản lý Dữ liệu Cảm biến và Điều khiển Thiết bị IoT.

Chủ đề kỹ thuật chính: Quản trị Firebase Console, Kiến trúc Dữ liệu NoSQL (JSON Tree), Database URL Routing, Cấu hình Bảo mật (Security Rules), Cơ chế Xác thực Ẩn danh (Anonymous Authentication), và Thao tác Đọc/Ghi Dữ liệu (CRUD Operations) qua API.

Vị trí trong hệ thống: Tầng 7 (Lưu trữ Dữ liệu Bền vững & Đám mây Toàn cầu).

  • Sự chuyển dịch Mô hình (Paradigm Shift): Ở Lab 6, bạn đã làm chủ Web Server Cục bộ, hệ thống chạy siêu tốc nhưng mang nhược điểm chí mạng: "Tắt điện là bay biến sạch dữ liệu". Lab 7 sẽ nhấc bổng hệ thống của bạn lên Google Cloud. Firebase cung cấp giải pháp Lưu trữ Bền vững (Persistence Data). Dữ liệu môi trường sẽ được lưu lại để phục vụ vẽ biểu đồ, phân tích Big Data hoặc làm Backend cấp dữ liệu cho Mobile App (Flutter/React Native) của các kỹ sư phần mềm.
  • Chuẩn bị cho tương lai: Làm chủ kiến trúc Backend-as-a-Service (BaaS) chính là mảnh ghép cuối cùng về mặt Phần mềm. Hoàn thành Lab này, bạn đã đủ năng lực làm một Đồ án Tốt nghiệp Công nghệ Thông tin trọn vẹn, sẵn sàng chuyển sang Lab 8 để thiết kế đóng gói phần cứng (Fritzing/PCB Layout).

3. Bản chất Học thuật: Tư duy Cơ sở Dữ liệu NoSQL (Firebase)

Thay đổi Tư duy: Quản lý Dữ liệu Dạng Cây (Tree), KHÔNG dùng Bảng (Table)

Sinh viên CNTT thường quen thuộc với CSDL Quan hệ (như MySQL/SQL Server) sử dụng Bảng, Hàng, Cột. Tuy nhiên, Firebase Realtime Database lại là một Cơ sở dữ liệu NoSQL (Phi quan hệ). Nó vận hành giống hệt như một file JSON khổng lồ chứa dữ liệu phân nhánh dạng Cây (Hierarchical Tree):

  1. Firebase Project: Là "Ngôi nhà" máy chủ Google chứa mọi dịch vụ. NodeMCU cần một "Chìa khóa" gọi là API Key để qua cửa bảo vệ của ngôi nhà này.
  2. Database URL (Endpoint): Là địa chỉ URL dẫn tới chính xác căn phòng chứa dữ liệu (Ví dụ: https://tram-iot-lab7.firebaseio.com/).
  3. Ghi dữ liệu (Write / Set): C++ trên ESP8266 không dùng lệnh INSERT INTO... phức tạp. Nó gửi lệnh trực tiếp tới một Nhánh (Node) cụ thể. Ví dụ: "Xin hãy Ghi đè con số 29.5 vào đường dẫn /NhaCuaToi/NhietDo". Dữ liệu sẽ tự động đồng bộ (Sync Real-time) qua WebSockets xuống mọi thiết bị đang mở App cùng lúc.
  4. Đọc dữ liệu (Read / Get): ESP8266 liên tục chọc vào Firebase hỏi: "Nhánh /NhaCuaToi/Den_D6 hiện tại đang chứa số 0 hay số 1?". Sau khi kéo (Get) con số này về RAM, vi điều khiển dùng lệnh digitalWrite để đóng/cắt điện áp cấp cho Relay/Đèn LED.

4. Mục tiêu giảng dạy / học tập

Kết thúc Lab 7, sinh viên phải minh chứng được năng lực:

  1. Thiết lập và quản trị hoàn chỉnh một Project trên giao diện Firebase Console (Hạ tầng Google Cloud).
  2. Thấu hiểu Quản trị Bảo mật: Giải thích được sự rủi ro cực độ của Test Mode (Mở toang cửa) và cơ chế khóa bảo vệ của Locked Mode thông qua việc tinh chỉnh cấu trúc Security Rules (.read, .write).
  3. Tích hợp API Đám mây: Khai báo và truyền chuẩn xác các tham số API_KEY, DATABASE_URL vào kiến trúc thư viện lõi C++.
  4. Thực thi Thao tác Data (CRUD): Lập trình đẩy dữ liệu cảm biến (Set Float) và kéo biến trạng thái điều khiển (Get Int) thông qua đối tượng chuyên chở FirebaseData.
  5. Xử lý Ngoại lệ Cơ sở dữ liệu: Nhận diện, bẫy lỗi và giải quyết triệt để sự cố Type Mismatch (Bất đồng bộ Kiểu dữ liệu - VD: Nhập một chuỗi String "1" trên Web nhưng trong code C++ lại dùng hàm getInt() để ép đọc).

5. Kiến thức nền (JSON Tree, Security Rules & Firebase ESP Client)

  • Cấu trúc JSON (NoSQL): Firebase lưu dữ liệu dưới định dạng Key-Value phân nhánh. 
    {
  "TramQuanTrac": {
    "DHT11": {
      "NhietDo": 28.5,
      "DoAm": 65.0
    },
    "ThietBi": {
      "Den_D6": 1
    }
  }
}
    Để lấy được giá trị Nhiệt độ, Mạch NodeMCU sẽ truy xuất API theo đường dẫn (Path): "/TramQuanTrac/DHT11/NhietDo".
  • Security Rules (Luật Tường lửa Firebase): Theo mặc định, Firebase chặn đứng mọi truy cập ẩn danh từ bên ngoài. Để Mạch có thể Ghi/Đọc dữ liệu mà chưa cần thiết kế hệ thống Đăng nhập Email/Pass phức tạp, trong không gian Lab ta phải chủ động hạ cấp Tường lửa sang Test Mode bằng mã JSON: { ".read": true, ".write": true }. Cảnh báo Học thuật: Ở Test Mode, bất kỳ kẻ nào dò ra URL của bạn đều có quyền xóa sạch Database!
  • Đối tượng FirebaseData (fbdo): Trong thư viện chuẩn công nghiệp Firebase_ESP_Client, biến fbdo (Firebase Data Object) đóng vai trò như một chiếc "Xe tải chở hàng". Bạn giao gói dữ liệu cho nó chở đi đẩy lên Cloud. Và khi nó quay về mang theo Response, bạn "mở thùng xe" ra (bằng lệnh fbdo.intData() hoặc fbdo.floatData()) để trích xuất dữ liệu nhận được từ Google.

8. Phân tích Sơ đồ phần cứng

Tái sử dụng Kiến trúc Phần cứng Cốt lõi

Không cần thay đổi bất kỳ sợi dây cáp nào so với Lab 2, 3, 6. Vi điều khiển MCU sẽ làm nhiệm vụ lấy Dữ liệu môi trường (Input) đẩy lên Cloud, và kéo Lệnh tham số (Command) từ Cloud xả ra chân Điều khiển bóng đèn (Output).

10. Quy trình Thực hành Từng bước

1 Pha 1: Quy hoạch Không gian Đám mây (Firebase Project Setup)

Mục đích: Khởi tạo cụm máy chủ và cấu hình mở toang rào cản bảo mật Firewall cho mục đích thực hành giáo dục.

  1. Đăng nhập console.firebase.google.com. Nhấn nút Add project. Nhập Tên Project (VD: IoT-Lab-7). Nhấn Continue. Gạt Tắt công tắc Google Analytics (chưa cần thiết cho IoT cơ bản). Nhấn Create project.
  2. Sau khi tiến vào màn hình quản trị chính, nhìn menu bên trái, bung mục Build > Chọn Realtime Database. Nhấn nút Create Database.
  3. Chọn Location vùng lưu trữ máy chủ (Khuyên chọn Singapore / asia-southeast1 để có độ trễ Ping thấp nhất về Việt Nam). Nhấn Next.
  4. KHẨN CẤP: Bắt buộc check tick chọn Start in test mode (Sẽ có dòng cảnh báo màu cam hiện lên). Nhấn Enable. Thao tác này sẽ tự động nạp đoạn rule .read: true, .write: true vào tường lửa của Database.
  5. Vào Project Settings (Icon Bánh răng) tìm lấy dải mật mã Web API Key. Copy Ghi chú ra file Notepad.
  6. Quay lại giao diện Realtime Database, copy dải Database URL. (Nhớ nguyên tắc xóa dấu xuyệt `/` ở cuối). Ghi chú ra Notepad.

2 Pha 2: Kiến tạo Dữ liệu Mẫu (JSON Tree Initialization)

Mục đích: Mồi sẵn một biến trạng thái đèn trên cấu trúc Web để con chip ESP8266 có mục tiêu trỏ tới để đọc (Get) khi boot lên.

  1. Ngay giữa màn hình Realtime Database (Tab Data), rê chuột vào cuối đoạn link gốc trên cùng sẽ thấy một dấu Cộng (+) mờ mờ hiện ra. Bấm vào dấu + đó.
  2. Ô Name (Đại diện cho Key): Gõ chữ Den_D6.
  3. Ô Value (Đại diện cho Giá trị): Gõ số 0. Lưu ý sinh tử: Gõ số 0 trần trụi, tuyệt đối không gõ chữ "0" có chứa dấu ngoặc kép hay kèm khoảng trắng. Firebase phân biệt ép kiểu cực kỳ khắt khe.
  4. Nhấn nút Add. Bạn vừa tạo xong 1 Nhánh Dữ liệu (Data Node) đầu đời. Dữ liệu số nguyên sẽ hiển thị highlight màu Xanh Lục/Cam.

3 Pha 3: Biên dịch Não bộ Nhúng IoT (Firmware Flashing)

Mục đích: Tích hợp thư viện lõi của Mobizt và đẩy mã nguồn C++ đồng bộ xuống Vi điều khiển.

  1. Mở phần mềm Arduino IDE. Kiểm tra kỹ Library Manager xem thư viện Firebase Arduino Client... của Mobizt đã hiện chữ INSTALLED chưa.
  2. Sao chép toàn bộ Mã nguồn Học thuật Fail-safe ở Phần 13 dán vào IDE.
  3. Thử Thách Vượt Bẫy: Cập nhật cẩn thận thông số WiFi, tìm và tự tay thay thế các đoạn <...> bằng API_KEY và DATABASE_URL thực tế của bạn. Đảm bảo code sạch sẽ, không dư ngoặc nhọn.
  4. Nhấn Upload. Upload xong mở ngay Serial Monitor (Baudrate 115200). Đè nút RST cứng trên board để reset mạch từ đầu. Chờ xem Board lấy được chữ ký Xác thực Token (Anonymous Auth) thành công không.

4 Pha 4: Thẩm định Đồng bộ Đám mây (Cloud Data Sync Testing)

Mục đích: Chứng minh giao thức Read (Kéo về) và Write (Đẩy lên) hoạt động Real-time ổn định xuyên quốc gia.

  1. Nghiệm thu Luồng Write (Uplink: ESP -> Cloud): Xếp cửa sổ Serial Monitor và cửa sổ Trình duyệt Web Firebase song song kế bên nhau. Cứ đúng 10 giây (theo Timer định thời C++), trên Serial sẽ báo [SYNC OK]. Lập tức nhìn sang Web Firebase, các Node /NhietDo và /DoAm sẽ tự động chớp nháy highlight viền cam (hoặc xanh lá) báo hiệu số liệu mới vừa bị ghi đè. Áp tay vào cảm biến DHT11, chờ 10s để thấy thông số trên web nảy vọt lên.
  2. Nghiệm thu Luồng Read (Downlink: Cloud -> ESP): Trên trang Web Firebase, đưa chuột bấm đúp trực tiếp vào con số 0 của Node Den_D6. Sửa nó thành số 1, gõ phím Enter. Ngay lập tức (độ trễ dưới 1 giây do cơ chế TCP Stream), đèn LED D6 trên phần cứng SÁNG RỰC LÊN! Đổi số 1 thành 0 lại trên Web, đèn tắt ngóm. Xin chúc mừng, Bạn đã thao túng thành công hệ thống Đám mây NoSQL của Google!

11. ⚠️ BẮT BUỘC: VƯỢT ẢI CÂU HỎI TRƯỚC KHI XEM CODE

Chứng minh Khả năng Tư duy CSDL Đám mây (Cloud Database Architect):

Sinh viên tuyệt đối không được phép chạm vào mã C++ nếu chưa giải thích được 6 điểm bản chất sau đây:

  1. Tại khâu setup Firebase, chúng ta bắt buộc phải cấu hình Security Rules sang chế độ Start in test mode (Tương đương .read: true, .write: true). Nếu chúng ta làm biếng bỏ qua bước này và để mặc định là Locked mode (false), chuyện gì sẽ hiển thị trên màn hình Serial Monitor của mạch khi nó nỗ lực gửi thông số nhiệt độ DHT11 lên?
  2. Khác biệt với CSDL SQL truyền thống (như MySQL), Firebase thuộc nhóm kiến trúc CSDL NoSQL. Thay vì dùng Bảng (Tables) và Cột (Columns), Firebase sử dụng cấu trúc lưu trữ dữ liệu dạng gì? Dấu gạch chéo / trong đường dẫn "/TramQuanTrac/Den_D6" thể hiện ý nghĩa gì trong cấu trúc đó?
  3. Trong thư viện C++ Firebase, đối tượng fbdo (Firebase Data Object) đóng chức năng gì trong câu lệnh Firebase.RTDB.getInt(&fbdo, "/Den_D6")? Hãy liên tưởng và so sánh nó với hình ảnh một chiếc xe tải đi chở hàng hóa.
  4. Bài toán Type Mismatch (Xung đột Kiểu Dữ Liệu): Nếu trên giao diện Web Firebase, chỗ cái Đèn thay vì gõ số, bạn cố tình gõ chữ "1" (có dấu ngoặc kép, tức dữ liệu dạng String/Chuỗi). Nhưng bên trong Code Arduino bạn lại ép gọi hàm fbdo.intData() (Yêu cầu trả về số nguyên Integer). Hệ thống vi điều khiển sẽ phản ứng ra sao với sự cố bất đồng bộ kiểu dữ liệu này? Đèn có sáng không?
  5. Xét về kiến trúc hệ thống vĩ mô: Việc lưu trữ thông số cảm biến vào Firebase Realtime Database mang lại ưu điểm "Lưu trữ Bền vững (Persistence)" và "Khả năng Mở rộng (Scalability)" to lớn thế nào so với việc bạn chỉ dựng một cái Web Server tĩnh nội bộ (Local Server) rớt điện là mất dữ liệu ở Lab 6?
  6. Trong code có hàm Firebase.signUp(&config, &auth, "", "") thực thi cơ chế Đăng nhập Ẩn danh (Anonymous Auth). 12. CHỐNG HỌC VẸT: Thảm họa Type Mismatch & Thư viện Lạc hậu

5 Dấu hiệu "Bệnh lý" Tố Cáo Sinh viên chỉ biết Copy-Paste Vô hồn ở Lab 7:

  2. Mạch Boot lên báo lỗi HTTP Code 404 (Not Found) liên tục. Căn bệnh: Copy dải DATABASE_URL nhưng lười không chịu đọc quy tắc: Phải xóa cái Dấu gạch chéo / ở tận cùng bên phải của link. HTTP đi tìm đường dẫn có 2 dấu xuyệt nên báo Không tồn tại.
  3. Mạch Boot lên báo lỗi Permission denied (401). Căn bệnh: Lười biếng không chịu cấu hình Tab Security Rules trên Web Firebase sang chế độ .read: true, .write: true. Tường lửa Firebase lạnh lùng đá văng mạch ra ngoài.

Căn bệnh: Ép mạch chạy vòng lặp đọc Firebase với tốc độ chóng mặt bằng cách xóa bỏ biến timer millis() giới hạn 10s. Dưới đây là bộ mã tích hợp công nghệ Firebase RTDB hiện đại nhất, hỗ trợ tự phục hồi kết nối, xác thực ẩn danh và bẫy lỗi tràn RAM (Token Helper).
CẢNH BÁO BẪY COPY CỦA MENTOR: Tại Khối 1, bạn BẮT BUỘC phải tự tay xóa bỏ các thẻ <...> và điền 4 tham số Mạng và API Tuyệt mật của riêng bạn vào. Bôi đen chép mù quáng nạp vào mạch sẽ dẫn đến Lỗi Đỏ Cú Pháp (Syntax Error) ngăn chặn biên dịch lập tức!

#include <ESP8266WiFi.h>
#include <Firebase_ESP_Client.h> // Thư viện lõi Mobizt (Bắt buộc phải cài qua Library Manager)
#include "DHT.h"

// Cung cấp cỗ máy chạy ngầm tự động gia hạn Token Auth để mạch không bị rớt mạng sau 1 tiếng
#include "addons/TokenHelper.h"
// Cung cấp các hàm in xuất Payload hỗ trợ xử lý luồng dữ liệu RTDB
#include "addons/RTDBHelper.h"

/* ======================================================================
   1. CẤU HÌNH MẠNG VÀ KREDENTIAL FIREBASE (BẮT BUỘC ĐIỀN)
   ====================================================================== */
#define WIFI_SSID "<NHẬP_TÊN_WIFI_CỦA_BẠN>"
#define WIFI_PASSWORD "<NHẬP_MẬT_KHẨU_WIFI>"

// Lấy từ Firebase Console -> Project Settings -> General -> Web API Key
#define API_KEY "<NHẬP_CHUỖI_API_KEY_BẮT_ĐẦU_BẰNG_CHỮ_AIzaSy_VÀO_ĐÂY>"

// Lấy từ Realtime Database. QUY TẮC THÉP: XÓA BỎ DẤU GẠCH CHÉO (/) Ở ĐUÔI CÙNG
#define DATABASE_URL "<NHẬP_URL_DATABASE_CỦA_BẠN_VÀO_ĐÂY>" 

/* ======================================================================
   2. CẤU HÌNH KIẾN TRÚC PHẦN CỨNG
   ====================================================================== */
#define DHTPIN 14        // Nối dây cáp Data DHT11 vào lỗ D5 (Tương ứng GPIO14)
#define DHTTYPE DHT11
DHT dht(DHTPIN, DHTTYPE);

#define LED_PIN 12       // Nối Đèn LED vào lỗ D6 (Tương ứng GPIO12)

/* ======================================================================
   3. KHỞI TẠO CÁC ĐỐI TƯỢNG HẠ TẦNG FIREBASE
   ====================================================================== */
FirebaseData fbdo;       // Đối tượng "Xe tải chở Hàng" (Chứa Request/Response Payload từ Cloud)
FirebaseAuth auth;       // Đối tượng Xác thực (Chứa Thông tin Chứng minh thư Đăng nhập)
FirebaseConfig config;   // Đối tượng Cấu hình (Chứa URL, API Key để định tuyến tìm máy chủ)

// Biến đếm thời gian (Đồng hồ cát) cho thuật toán Đa nhiệm Non-blocking (Timer)
unsigned long sendDataPrevMillis = 0; 
unsigned long getLedPrevMillis = 0;

bool signupOK = false;   // Cờ trạng thái đánh dấu việc đăng ký lấy Token thành công hay chưa

void setup() {
  Serial.begin(115200);
  dht.begin();
  pinMode(LED_PIN, OUTPUT);
  digitalWrite(LED_PIN, LOW); // Ghìm phần cứng tắt đèn an toàn khi vừa boot lên

  // --- KẾT NỐI WIFI ---
  WiFi.begin(WIFI_SSID, WIFI_PASSWORD);
  Serial.print("\n>> Đang đàm phán xin IP từ Wi-Fi");
  while (WiFi.status() != WL_CONNECTED) {
    Serial.print(".");
    delay(300);
  }
  Serial.println("\n>> Đã vào mạng nội bộ. IP Cục Bộ của bạn là: " + WiFi.localIP().toString());

  // --- KHỞI TẠO LÕI MÁY TRẠM FIREBASE ---
  Serial.printf(">> Đang nạp Firebase Client Version v%s\n", FIREBASE_CLIENT_VERSION);
  config.api_key = API_KEY;
  config.database_url = DATABASE_URL;

  // Thuật toán Xác thực Ẩn danh (Anonymous Auth):
  // Dù Database mở toang bằng Test Mode, các thư viện hiện đại của Google vẫn ép ESP8266
  // phải có 1 mã định danh (Token) để bảo vệ hạ tầng, tránh bị hệ thống Anti-Spam (DDOS) chặn lại.
  if (Firebase.signUp(&config, &auth, "", "")) {
    Serial.println(">> Đăng ký Lấy Token Ẩn danh thành công! Đã thông chốt Tường lửa Firewall.");
    signupOK = true;
  } else {
    Serial.printf(">> [CẢNH BÁO LỖI] Lấy Token thất bại: %s\n", config.signer.signupError.message.c_str());
  }

  // Khai báo gán hàm callback xử lý việc cấp lại Token ngầm khi Token cũ hết hạn (Mỗi 60 phút)
  config.token_status_callback = tokenStatusCallback; 

  // Khởi động Dịch vụ (Service) Firebase chạy ngầm song song cùng Hệ điều hành RTOS
  Firebase.begin(&config, &auth);
  Firebase.reconnectWiFi(true); // Bật tính năng Tự động phục hồi kết nối nếu Router rớt WiFi giữa chừng
}

void loop() {
  unsigned long currentMillis = millis(); // Nhìn lên đồng hồ hệ thống xem đã trôi qua bao nhiêu mili-giây

  /* ======================================================================
     TÁC VỤ 1: ĐỌC DỮ LIỆU TỪ FIREBASE (PULL - LẤY LỆNH ĐIỀU KHIỂN XUỐNG)
     Bản chất: Hàm getInt() chạy định kỳ để quét sự thay đổi của Node /Den_D6 trên mây
     ====================================================================== */
  // Chỉ mạnh dạn hỏi Firebase nếu API Token đã được cấp phát (Ready) 
  // Và khoảng cách giữa các lần hỏi tối thiểu là 1000ms (1s) để tránh sập máy chủ.
  if (Firebase.ready() && signupOK && (currentMillis - getLedPrevMillis > 1000 || getLedPrevMillis == 0)) {
    getLedPrevMillis = currentMillis; // Reset lại đồng hồ đếm lùi nhánh Get
    
    // Gửi gói Request: "Xin chào Google, cho tôi xin giá trị Số nguyên (Int) tại Node /Den_D6"
    if (Firebase.RTDB.getInt(&fbdo, "/Den_D6")) {
      
      // KỸ THUẬT PHÒNG THỦ: Nếu Cloud đồng ý, hàm dataType() sẽ soi xem số liệu kéo về có đúng chuẩn là số (int) không
      // Phòng trường hợp User nhập bậy bạ chữ Text trên Web làm treo mạch.
      if (fbdo.dataType() == "int") {
        
        int ledCommand = fbdo.intData(); // Mở thùng xe fbdo lấy cục con số ra
        
        // Điều hướng Logic chốt Phần cứng
        if (ledCommand == 1) {
          digitalWrite(LED_PIN, HIGH);
        } else {
          digitalWrite(LED_PIN, LOW);
        }
      }
    } else {
      // Bẫy lỗi Debug: Có thể Link URL sai, Data Mismatch (Bắt int nhưng Firebase trả String), hoặc rớt mạng
      Serial.println("[LỖI GET] Kéo biến Đèn thất bại: " + fbdo.errorReason());
    }
  }

  /* ======================================================================
     TÁC VỤ 2: GHI DỮ LIỆU LÊN FIREBASE (PUSH - BÁO CÁO CẢM BIẾN VIỄN TRẮC)
     Luật bảo vệ máy chủ: Chỉ được phép báo cáo cập nhật nhiệt độ 10 giây (10000ms) 1 lần
     ====================================================================== */
  if (Firebase.ready() && signupOK && (currentMillis - sendDataPrevMillis > 10000 || sendDataPrevMillis == 0)) {
    sendDataPrevMillis = currentMillis; // Reset lại đồng hồ đếm lùi nhánh Set

    float t = dht.readTemperature();
    float h = dht.readHumidity();

    // Khắc phục ngoại lệ (Exception) của Phần cứng Hardware
    if (isnan(t) || isnan(h)) {
      Serial.println("[LỖI HARDWARE] Cảm biến DHT11 không phản hồi!");
      return; // Dừng lại tại đây, tuyệt đối không đẩy rác (NaN) lên mây làm bẩn Database
    }

    // 1. Ghi đè (Set Float) thông số Nhiệt độ vào nhánh Cây có tên "/NhietDo"
    if (Firebase.RTDB.setFloat(&fbdo, "/NhietDo", t)) {
      Serial.print(">> [SYNC OK] Đã tải lên Đám mây Nhiệt Độ: ");
      Serial.println(t);
    } else {
      Serial.println(">> [LỖI SET] Lưu Nhiệt độ thất bại: " + fbdo.errorReason());
    }

    // 2. Ghi đè (Set Float) thông số Độ ẩm vào nhánh Cây có tên "/DoAm"
    if (Firebase.RTDB.setFloat(&fbdo, "/DoAm", h)) {
      Serial.print(">> [SYNC OK] Đã tải lên Đám mây Độ Ẩm: ");
      Serial.println(h);
    } else {
      Serial.println(">> [LỖI SET] Lưu Độ ẩm thất bại: " + fbdo.errorReason());
    }
  }
}

  2. Cơ chế Test Mode (.read: true, .write: true) là một thảm họa bảo mật IoT nếu bạn triển khai Đồ án mang bán ra thị trường.
