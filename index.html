2. Tổng quan Lab

Tên chuẩn hóa: Thiết lập Cơ sở Dữ liệu Đám mây Phi quan hệ (NoSQL) để Quản lý Dữ liệu Cảm biến và Điều khiển Thiết bị IoT.

Chủ đề kỹ thuật chính: Firebase Console Project, Kiến trúc Dữ liệu NoSQL (JSON Tree), Database URL Định tuyến, Cấu hình Bảo mật (Security Rules), Cơ chế Xác thực Ẩn danh (Anonymous Authentication), và Thao tác Đọc/Ghi Dữ liệu (CRUD Operations) qua API.

Vị trí trong hệ thống: Tầng 7 (Lưu trữ Dữ liệu & Đám mây Toàn cầu).

  • Sự chuyển dịch Mô hình (Paradigm Shift): Ở Lab 6, bạn làm chủ Web Server Cục bộ, nhưng nhược điểm là "tắt điện thì mất sạch dữ liệu". Lab 7 đưa hệ thống của bạn lên Google Cloud. Firebase cung cấp giải pháp Lưu trữ Bền vững (Persistence). Dữ liệu môi trường sẽ được lưu lại mãi mãi để phục vụ vẽ biểu đồ, phân tích Data Analytics hoặc kết nối với Mobile App (Flutter/React Native) sau này.
  • Chuẩn bị cho tương lai: Làm chủ kiến trúc Backend-as-a-Service (BaaS) là mảnh ghép cuối cùng về mặt Phần mềm. Sau Lab này, bạn đã đủ năng lực làm Đồ án trọn vẹn, sẵn sàng chuyển sang Lab 8 để thiết kế vỏ bọc phần cứng (Fritzing/PCB).

3. Bản chất Học thuật của Cơ sở Dữ liệu NoSQL (Firebase)

Tư duy Quản lý Dữ liệu Dạng Cây (Tree), KHÔNG dùng Bảng (Table)

Sinh viên IT thường quen với CSDL Quan hệ (MySQL/SQL Server) sử dụng Bảng, Hàng, Cột. Firebase Realtime Database lại là một Cơ sở dữ liệu NoSQL (Phi quan hệ). Nó vận hành như một file JSON khổng lồ chứa dữ liệu phân cấp dạng Cây (Hierarchical Tree):

  1. Firebase Project: Là "Ngôi nhà" trên máy chủ Google chứa mọi dịch vụ. NodeMCU cần một "Chìa khóa" gọi là API Key để qua cổng ngôi nhà này.
  2. Database URL (Endpoint): Là địa chỉ chính xác của phòng chứa dữ liệu (Ví dụ: https://tram-iot-lab7.firebaseio.com/).
  3. Ghi dữ liệu (Write / Set): ESP8266 không gửi lệnh INSERT INTO... phức tạp. Nó gửi lệnh trực tiếp tới một Nhánh (Node) cụ thể. Ví dụ: "Ghi đè số 29.5 vào đường dẫn /NhaCuaToi/NhietDo". Dữ liệu sẽ tự động đẩy (Sync) xuống mọi điện thoại đang mở App cùng lúc.
  4. Đọc dữ liệu (Read / Get): ESP8266 liên tục chọc vào Firebase hỏi: "Nhánh /NhaCuaToi/Den_Phong_Khach đang chứa số 0 hay số 1?". Sau khi kéo (Get) số này về, vi điều khiển dùng lệnh digitalWrite để bật/tắt Relay/LED.

4. Mục tiêu giảng dạy / học tập

Kết thúc Lab 7, sinh viên phải minh chứng được năng lực:

  1. Thiết lập và quản trị hoàn chỉnh một Project trên Firebase Console (Google Cloud).
  2. Thấu hiểu Quản trị Bảo mật: Giải thích được sự khác biệt giữa Test Mode (Mở toang cửa) và Locked Mode (Có bảo vệ) thông qua Security Rules (.read, .write).
  3. Tích hợp API: Khai báo chuẩn xác các thông số API_KEY và DATABASE_URL vào kiến trúc thư viện C++.
  4. Thực thi Thao tác Data (CRUD): Lập trình đẩy dữ liệu cảm biến (Set/Push) và đọc biến trạng thái điều khiển (Get) thông qua đối tượng FirebaseData.
  5. Xử lý Ngoại lệ (Exception Handling): Bẫy lỗi và giải quyết triệt để sự cố Type Mismatch (Bất đồng bộ Kiểu dữ liệu - VD: Đọc một chuỗi String nhưng lại dùng hàm getInt()).

5. Kiến thức nền (Cấu trúc Cây, Security Rules & Firebase ESP Client)

  • Cấu trúc JSON (NoSQL): Firebase lưu dữ liệu dưới định dạng Key-Value phân nhánh. 
    {
  "TramQuanTrac": {
    "DHT11": {
      "NhietDo": 28.5,
      "DoAm": 65
    },
    "ThietBi": {
      "DenLED": 1
    }
  }
}
    Để lấy giá trị Nhiệt độ, Mạch NodeMCU sẽ truy cập đường dẫn (Path): "/TramQuanTrac/DHT11/NhietDo".
  • Security Rules (Luật Bảo Mật Firebase): Firebase mặc định chặn mọi truy cập ẩn danh. Để Mạch có thể Ghi/Đọc dữ liệu mà chưa cần thiết kế hệ thống Đăng nhập phức tạp, ta phải hạ cấp Luật bảo mật sang Test Mode: { ".read": true, ".write": true }. Cảnh báo: Ở Test Mode, bất kỳ ai có URL của bạn đều có quyền xóa sạch Database!
  • Đối tượng FirebaseData (fbdo): Trong thư viện hiện đại Firebase_ESP_Client, biến fbdo (Firebase Data Object) đóng vai trò như một chiếc "Xe tải chở hàng". Bạn giao gói dữ liệu cho nó chở đi, và khi nó quay về, bạn "mở thùng xe" ra (bằng lệnh fbdo.intData()) để lấy dữ liệu nhận được từ Google.

10. Quy trình Thực hành Từng bước

1 Pha 1: Quy hoạch Đám mây (Firebase Project Setup)

Mục đích: Khởi tạo cụm máy chủ và mở toang rào cản bảo mật cho mục đích giáo dục.

  1. Đăng nhập console.firebase.google.com. Nhấn Add project. Nhập Tên Project (VD: IoT-Lab-7). Nhấn Continue. Tắt nút Google Analytics (không cần thiết). Nhấn Create project.
  2. Sau khi vào màn hình chính, nhìn menu bên trái, chọn Build > Realtime Database. Nhấn Create Database.
  3. Chọn Location (Khuyên chọn Singapore/Asia-southeast1 cho độ trễ thấp nhất về VN). Nhấn Next.
  4. KHẨN CẤP: Bắt buộc check chọn Start in test mode (Sẽ có cảnh báo màu cam). Nhấn Enable. Việc này sẽ nạp đoạn rule .read: true, .write: true vào tường lửa.
  5. Vào Project Settings (Icon Bánh răng) lấy Web API Key. Ghi chú ra file Text.
  6. Quay lại Realtime Database, copy dải Database URL. Nhớ nguyên tắc xóa dấu xuyệt (/). Ghi chú ra file Text.

2 Pha 2: Kiến tạo Dữ liệu Mẫu (JSON Tree Creation)

Mục đích: Mồi sẵn biến trạng thái để ESP8266 có cái để đọc (Get).

  1. Ngay giữa màn hình Realtime Database, rê chuột vào cuối đoạn link gốc sẽ thấy dấu Cộng (+) mờ mờ hiện ra. Bấm vào dấu + đó.
  2. Ô Name gõ chữ: Den_D6. Ô Value gõ số: 0. (Lưu ý gõ số 0 trần trụi, tuyệt đối không gõ "0" có ngoặc kép).
  3. Nhấn Add. Bạn vừa tạo xong 1 Nhánh Dữ liệu (Data Node).

3 Pha 3: Biên dịch Não bộ IoT (Firmware Flashing)

Mục đích: Tích hợp thư viện Mobizt và đẩy mã nguồn xuống Vi điều khiển.

  1. Mở Arduino IDE. Kiểm tra kỹ Library Manager xem thư viện Firebase của Mobizt đã hiện chữ INSTALLED chưa.
  2. Sao chép toàn bộ Mã nguồn Học thuật ở Phần 13 vào IDE.
  3. Cập nhật cẩn thận thông số WiFi, API_KEY và DATABASE_URL.
  4. Nhấn Upload. Upload xong mở ngay Serial Monitor (Baudrate 115200). Chờ xem Board lấy được chữ ký Xác thực (Anonymous Token) không.

4 Pha 4: Thẩm định Đồng bộ Đám mây (Cloud Data Sync Test)

Mục đích: Chứng minh giao thức Read (Kéo) và Write (Đẩy) hoạt động Real-time.

  1. Nghiệm thu Write (ESP -> Cloud): Xếp cửa sổ Serial Monitor và cửa sổ Trình duyệt Web Firebase kế bên nhau. Cứ đúng 10 giây (theo Timer C++), trên Serial báo Ghi thành công. Lập tức nhìn sang Web Firebase, các Node /NhietDo và /DoAm sẽ tự động chớp chớp viền cam (hoặc xanh) báo hiệu số liệu vừa bị ghi đè. Áp tay vào cảm biến, chờ 10s để thấy số nhảy.
  2. Nghiệm thu Read (Cloud -> ESP): Trên trang Web Firebase, bấm đúp trực tiếp vào số 0 của Node Den_D6. Gõ số 1, nhấn Enter. Ngay lập tức (độ trễ dưới 1s), đèn LED D6 trên phần cứng sáng rực! Đổi số 1 thành 0, đèn tắt ngóm. Bạn đã làm chủ đám mây Google!

11. Sinh viên bắt buộc trả lời trước khi nhận Code

Chứng minh Khả năng Tư duy CSDL Đám mây (Cloud Database):
  1. Tại khâu setup Firebase, chúng ta phải cấu hình Security Rules sang Start in test mode. Nếu chúng ta bỏ qua bước này và để mặc định là Locked mode, chuyện gì sẽ hiển thị trên màn hình Serial Monitor của Arduino khi mạch nỗ lực gửi thông số nhiệt độ?
  2. Trong thư viện Firebase, đối tượng fbdo (Firebase Data Object) đóng chức năng gì trong lệnh Firebase.RTDB.getInt(&fbdo, "/Den_D6")?
  3. Bài toán Type Mismatch: Nếu trên giao diện Firebase, chỗ cái Đèn bạn gõ chữ "BẬT" (dữ liệu dạng String/Chuỗi). Nhưng trong Code Arduino bạn lại gọi hàm fbdo.intData() (Yêu cầu trả về số nguyên). Hệ thống vi điều khiển sẽ phản ứng ra sao với sự cố bất đồng bộ kiểu dữ liệu này?
  4. Xét về kiến trúc: Việc lưu trữ tham số vào Firebase Realtime Database mang lại ưu điểm "Lưu trữ Dài hạn (Persistence)" và "Mở rộng Ứng dụng (Scalability)" lớn lao thế nào so với việc bạn chỉ dựng một cái Web Server tĩnh nội bộ (Local Server) ở Lab 6?

12. CẤM COPY MÙ QUÁNG: Thảm họa Type Mismatch & Thư viện Lạc hậu

Tại sao Code Copy trên Mạng thường xuyên Đổ vỡ?

1. Thư viện "Hết Hạn Sử Dụng": Tuyệt đại đa số bài hướng dẫn tiếng Việt cũ (từ 2018-2021) đều dạy dùng thư viện FirebaseArduino.h. Tuy nhiên, Google đã thay đổi giao thức cấp phát Chứng chỉ bảo mật (Root SSL). Hậu quả: Dùng thư viện cũ, mạch sẽ văng lỗi SSL Fingerprint Mismatch liên tục và chết cứng. Đó là lý do Lab này bắt buộc áp dụng Thư viện Firebase_ESP_Client (Mobizt) - Chuẩn công nghiệp hiện tại.

2. Vết xước "Type Mismatch" (Sai Kiểu Dữ Liệu): Trong CSDL NoSQL của Firebase, số 0 (Integer) và chữ "0" (String - bị kẹp trong ngoặc kép) là 2 thực thể hoàn toàn khác nhau. Khi sinh viên lên giao diện Web Firebase tạo biến Den_D6, rất hay lỡ tay gõ dư ngoặc kép hoặc gõ khoảng trắng. Khi đó, hàm getInt() của C++ đọc trúng chuỗi String sẽ lập tức thất bại và trả về số 0 giả (hoặc rác), khiến đèn bị liệt không thể bật sáng.

3. Vụ rò rỉ Test Mode: Để tiết kiệm thời gian dạy học, Lab này dùng Test Mode (Cấp quyền Đọc/Ghi tự do cho mọi khách vãng lai). Trong thực tế sản xuất thương mại, đây là "Hành vi Tự sát". Hacker dùng tool quét URL có thể chèn mã độc hoặc xóa sạch Database của bạn. Đối với Đồ án môn học, tuyệt đối phải học cách khóa Rules thành auth != null và dùng hàm Đăng nhập bằng Email/Password.

13. Phân tích Code Chuẩn: Firebase ESP Client & Cơ chế Anonymous Auth

Dưới đây là bộ mã tích hợp công nghệ Firebase RTDB hiện đại nhất, hỗ trợ tự phục hồi kết nối và bẫy lỗi tràn RAM (Token Helper).

#include <ESP8266WiFi.h>
#include <Firebase_ESP_Client.h> // Thư viện Mobizt (Bắt buộc cài qua Library Manager)
#include "DHT.h"

// Provide the token generation process info.
#include "addons/TokenHelper.h"
// Provide the RTDB payload printing info and other helper functions.
#include "addons/RTDBHelper.h"

/* ======================================================================
   1. CẤU HÌNH MẠNG VÀ KREDENTIAL FIREBASE (TUYỆT MẬT)
   ====================================================================== */
#define WIFI_SSID "WIFI_CUA_BAN"
#define WIFI_PASSWORD "MAT_KHAU"

// Lấy từ Firebase Console -> Project Settings -> General -> Web API Key
#define API_KEY "AIzaSy_Ghi_Chuoi_Key_Bi_Mat_Vao_Day"

// Lấy từ Realtime Database. QUY TẮC THÉP: Xóa dấu gạch chéo (/) ở cuối cùng
#define DATABASE_URL "https://iot-lab-7-xyz-rtdb.asia-southeast1.firebasedatabase.app" 

/* ======================================================================
   2. CẤU HÌNH KIẾN TRÚC PHẦN CỨNG
   ====================================================================== */
#define DHTPIN 14        // Nối dây Data DHT11 vào D5
#define DHTTYPE DHT11
DHT dht(DHTPIN, DHTTYPE);

#define LED_PIN 12       // Nối Đèn LED vào D6

/* ======================================================================
   3. KHỞI TẠO CÁC ĐỐI TƯỢNG HẠ TẦNG FIREBASE
   ====================================================================== */
FirebaseData fbdo;       // Đối tượng chở Hàng (Chứa Request/Response Payload)
FirebaseAuth auth;       // Đối tượng Xác thực (Chứa Thông tin Đăng nhập)
FirebaseConfig config;   // Đối tượng Cấu hình (Chứa URL, API Key)

unsigned long sendDataPrevMillis = 0; // Biến đánh dấu thời gian cho thuật toán Non-blocking

void setup() {
  Serial.begin(115200);
  dht.begin();
  pinMode(LED_PIN, OUTPUT);
  digitalWrite(LED_PIN, LOW); // Ghìm phần cứng tắt khi boot

  // --- KẾT NỐI WIFI ---
  WiFi.begin(WIFI_SSID, WIFI_PASSWORD);
  Serial.print("\n>> Đang đàm phán Wi-Fi");
  while (WiFi.status() != WL_CONNECTED) {
    Serial.print(".");
    delay(300);
  }
  Serial.println("\n>> Đã vào mạng nội bộ. IP: " + WiFi.localIP().toString());

  // --- KHỞI TẠO LÕI FIREBASE ---
  Serial.printf(">> Nạp Firebase Client v%s\n", FIREBASE_CLIENT_VERSION);
  config.api_key = API_KEY;
  config.database_url = DATABASE_URL;

  // Thuật toán Xác thực Ẩn danh (Anonymous Auth):
  // Dù Database mở Test Mode, các thư viện hiện đại của Google vẫn ép ESP8266
  // phải có 1 mã định danh (Token) để tránh bị hệ thống Anti-Spam (DDOS) chặn lại.
  if (Firebase.signUp(&config, &auth, "", "")) {
    Serial.println(">> Đăng ký Lấy Token Ẩn danh thành công!");
  } else {
    Serial.printf(">> [CẢNH BÁO LỖI] Token thất bại: %s\n", config.signer.signupError.message.c_str());
  }

  // Khởi động Dịch vụ (Service) Firebase chạy ngầm cùng RTOS
  Firebase.begin(&config, &auth);
  Firebase.reconnectWiFi(true); // Bật tính năng tự động phục hồi kết nối nếu rớt WiFi
}

void loop() {
  unsigned long currentMillis = millis(); // Nhìn đồng hồ hệ thống

  /* ======================================================================
     TÁC VỤ 1: ĐỌC DỮ LIỆU TỪ FIREBASE (PULL - LẤY LỆNH ĐIỀU KHIỂN)
     Bản chất: Hàm getInt() chạy liên tục quét sự thay đổi của Node /Den_D6
     ====================================================================== */
  // Chỉ hỏi Firebase nếu API Token đã được cấp phát và cấp phép (Ready)
  if (Firebase.ready()) {
    
    // Gửi gói Request: "Cho tôi xin giá trị Số nguyên tại Node /Den_D6"
    if (Firebase.RTDB.getInt(&fbdo, "/Den_D6")) {
      
      // Nếu Cloud đồng ý, mở thùng xe fbdo lấy dữ liệu ra
      int ledCommand = fbdo.intData(); 
      if (ledCommand == 1) {
        digitalWrite(LED_PIN, HIGH);
      } else {
        digitalWrite(LED_PIN, LOW);
      }
    } else {
      // Bẫy lỗi: Link sai, Data Mismatch, hoặc rớt mạng
      Serial.println("[LỖI GET] Đọc biến Đèn thất bại: " + fbdo.errorReason());
    }
  }

  /* ======================================================================
     TÁC VỤ 2: GHI DỮ LIỆU LÊN FIREBASE (PUSH - BÁO CÁO CẢM BIẾN)
     Luật bảo vệ máy chủ: Chỉ được phép báo cáo 10 giây (10000ms) 1 lần
     ====================================================================== */
  if (Firebase.ready() && (currentMillis - sendDataPrevMillis > 10000 || sendDataPrevMillis == 0)) {
    sendDataPrevMillis = currentMillis; // Reset lại đồng hồ đếm

    float t = dht.readTemperature();
    float h = dht.readHumidity();

    if (isnan(t) || isnan(h)) {
      Serial.println("[LỖI HARDWARE] Cảm biến DHT11 không phản hồi!");
      return; // Dừng lại, không đẩy rác (NaN) lên mây
    }

    // 1. Ghi đè (Set Float) Nhiệt độ vào nhánh Cây
    if (Firebase.RTDB.setFloat(&fbdo, "/NhietDo", t)) {
      Serial.print(">> [SYNC OK] Nhiệt Độ: ");
      Serial.println(t);
    } else {
      Serial.println(">> [LỖI SET] Lưu Nhiệt độ thất bại: " + fbdo.errorReason());
    }

    // 2. Ghi đè (Set Float) Độ ẩm vào nhánh Cây
    if (Firebase.RTDB.setFloat(&fbdo, "/DoAm", h)) {
      Serial.print(">> [SYNC OK] Độ Ẩm: ");
      Serial.println(h);
    } else {
      Serial.println(">> [LỖI SET] Lưu Độ ẩm thất bại: " + fbdo.errorReason());
    }
  }
}
