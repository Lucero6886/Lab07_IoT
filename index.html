🔍 2. Tổng quan Lab

Tên chuẩn hóa: Thiết lập Cơ sở Dữ liệu Đám mây Phi quan hệ (NoSQL) để Quản lý Dữ liệu Cảm biến và Điều khiển Thiết bị IoT qua mạng lưới Toàn cầu.

Chủ đề kỹ thuật chính: Quản trị Firebase Console, Kiến trúc Dữ liệu NoSQL (JSON Tree), Database URL Routing, Cấu hình Bảo mật (Security Rules), Cơ chế Xác thực Ẩn danh (Anonymous Authentication), và Thao tác Đọc/Ghi Dữ liệu (CRUD) qua API.

Vị trí trong hệ thống: Tầng 7 (Lưu trữ Dữ liệu Bền vững & Đám mây Toàn cầu).

  • Sự chuyển dịch Mô hình (Paradigm Shift): Ở Lab 6, bạn đã làm chủ Web Server Cục bộ, hệ thống chạy siêu tốc trong mạng LAN nhưng mang nhược điểm chí mạng: "Tắt điện là bay biến sạch dữ liệu". Lab 7 sẽ nhấc bổng hệ thống của bạn lên Google Cloud. Firebase cung cấp giải pháp Lưu trữ Bền vững (Persistence Data). Mọi số liệu đo lường sẽ được lưu trữ an toàn, phục vụ vẽ biểu đồ, phân tích Big Data hoặc làm Backend cấp dữ liệu cho Mobile App.
  • Đính chính khái niệm "Real-time": Cần tránh việc hiểu "Firebase Realtime Database" theo nghĩa của Hệ thời gian thực cứng (Deterministic Hard Real-time) dùng trong công nghiệp tự động hóa. Trong môn học này, "Real-time" mang ý nghĩa là Đồng bộ cập nhật gần thời gian thực (Near real-time sync) thông qua cơ chế của nền tảng Cloud.

💡 3. Bản chất Học thuật: Tư duy Cơ sở Dữ liệu NoSQL

Thay đổi Tư duy: Quản lý Dữ liệu Dạng Cây (Tree), KHÔNG dùng Bảng (Table)

Sinh viên CNTT thường quen thuộc với CSDL Quan hệ (như MySQL/SQL Server) sử dụng Bảng, Hàng, Cột. Tuy nhiên, Firebase Realtime Database lại là một Cơ sở dữ liệu NoSQL (Phi quan hệ). Nó vận hành giống hệt như một file JSON khổng lồ chứa dữ liệu phân nhánh dạng Cây (Hierarchical Tree):

  1. Firebase Project: Là "Ngôi nhà" máy chủ Google chứa mọi dịch vụ. NodeMCU cần một "Định danh dự án" gọi là API Key để biết cần kết nối vào ngôi nhà nào. (Lưu ý: API Key không phải là chìa khóa bảo mật tuyệt đối, nó chỉ là tấm biển chỉ đường).
  2. Database URL (Endpoint): Là địa chỉ URL dẫn tới chính xác căn phòng chứa dữ liệu (Ví dụ: https://tram-iot-lab7.firebaseio.com/).
  3. Ghi dữ liệu (Write / Set): C++ trên ESP8266 không dùng lệnh INSERT INTO... phức tạp. Nó gửi lệnh trực tiếp tới một Nhánh (Node) cụ thể. Ví dụ: "Xin hãy Ghi đè con số 29.5 vào đường dẫn /NhaCuaToi/NhietDo".
  4. Đọc dữ liệu (Read / Get): ESP8266 gửi truy vấn tới Firebase hỏi: "Nhánh /NhaCuaToi/Den_D6 hiện tại đang chứa số 0 hay số 1?". Sau khi kéo (Get) con số này về RAM, vi điều khiển dùng lệnh digitalWrite để đóng/cắt điện áp cho phần cứng.

🎯 4. Mục tiêu học tập

Kết thúc Lab 7, sinh viên phải minh chứng được năng lực:

  1. Thiết lập và quản trị hoàn chỉnh một Project trên giao diện Firebase Console (Hạ tầng Google Cloud).
  2. Thấu hiểu Quản trị Bảo mật: Giải thích được sự rủi ro cực độ của Test Mode (Mở toang cửa) và cơ chế khóa bảo vệ của Locked Mode thông qua việc tinh chỉnh cấu trúc Security Rules (.read, .write).
  3. Tích hợp API Đám mây: Khai báo và truyền chuẩn xác các tham số API_KEY, DATABASE_URL vào kiến trúc thư viện lõi C++.
  4. Thực thi Thao tác Data (CRUD): Lập trình đẩy dữ liệu cảm biến (Set Float) và kéo biến trạng thái điều khiển (Get Int) thông qua đối tượng chuyên chở FirebaseData.
  5. Xử lý Ngoại lệ Cơ sở dữ liệu: Nhận diện, bẫy lỗi và giải quyết triệt để sự cố Type Mismatch (Bất đồng bộ Kiểu dữ liệu - VD: Nhập một chuỗi String "1" trên Web nhưng trong code C++ lại dùng hàm getInt() để ép đọc).

📚 5. Kiến thức nền (JSON Tree & Security Rules)

  • Cấu trúc JSON (NoSQL): Firebase lưu dữ liệu dưới định dạng Key-Value phân nhánh. 
    {
  "TramQuanTrac": {
    "DHT11": {
      "NhietDo": 28.5,
      "DoAm": 65.0
    },
    "ThietBi": {
      "Den_D6": 1
    }
  }
}
    Để lấy được giá trị Nhiệt độ, Mạch NodeMCU sẽ truy xuất API theo đường dẫn (Path): "/TramQuanTrac/DHT11/NhietDo".
  • Security Rules (Luật Tường lửa Firebase): Theo mặc định, Firebase chặn đứng mọi truy cập ẩn danh từ bên ngoài. Trong không gian Lab, ta tạm thời hạ cấp Tường lửa sang Test Mode bằng mã JSON: { ".read": true, ".write": true } để dễ dàng thực hành thao tác API.
    ⚠️ Cảnh báo Học thuật Nghiêm trọng: Chế độ Test Mode CHỈ ĐƯỢC PHÉP DÙNG trong môi trường Lab. Tuyệt đối KHÔNG sử dụng cho Sản phẩm thực tế (Production). Việc mở toang cửa true/true cho phép bất cứ ai vô tình biết được URL đều có quyền chèn mã độc hoặc xóa sạch toàn bộ Database của bạn. Trong thực tế, hệ thống bắt buộc phải xác thực bằng Firebase Authentication và Rule auth != null.
  • Đối tượng FirebaseData (fbdo): Trong thư viện chuẩn công nghiệp Firebase_ESP_Client, biến fbdo (Firebase Data Object) đóng vai trò như một chiếc "Xe tải chở hàng". Bạn giao gói dữ liệu cho nó chở đi đẩy lên Cloud. Và khi nó quay về mang theo Response, bạn "mở thùng xe" ra (bằng lệnh fbdo.intData()) để trích xuất dữ liệu nhận được từ Google.

⚡ 8. Sơ đồ Đấu nối Phần cứng

Tái sử dụng Kiến trúc Phần cứng Cốt lõi

Không cần thay đổi bất kỳ sợi dây cáp nào so với Lab 2, 3, 6. Vi điều khiển MCU sẽ làm nhiệm vụ lấy Dữ liệu môi trường (Input) đẩy lên Cloud, và kéo Lệnh tham số (Command) từ Cloud xả ra chân Điều khiển bóng đèn (Output).

  • Cảm biến Môi trường DHT11 (Chân Data): Nối vào lỗ D5 (GPIO14).
  • Thiết bị Chấp hành LED (Chân Anode dài + Trở hạn dòng 220Ω): Nối vào lỗ D6 (GPIO12). Chân Cathode ngắn nối GND.

🚀 10. Quy trình Thực hành Từng bước

1 Pha 1: Quy hoạch Không gian Đám mây (Firebase Project Setup)

Mục đích: Khởi tạo cụm máy chủ và tạm cấu hình mở rào cản bảo mật Firewall cho mục đích thực hành giáo dục.

  1. Đăng nhập console.firebase.google.com. Nhấn nút Add project. Nhập Tên Project (VD: IoT-Lab-7). Nhấn Continue. Gạt Tắt công tắc Google Analytics (chưa cần thiết cho IoT cơ bản). Nhấn Create project.
  2. Sau khi tiến vào màn hình quản trị chính, nhìn menu bên trái, bung mục Build ➔ Chọn Realtime Database. Nhấn nút Create Database.
  3. Chọn Location vùng lưu trữ máy chủ (Khuyên chọn Singapore / asia-southeast1 để có độ trễ Ping thấp nhất về Việt Nam). Nhấn Next.
  4. KHẨN CẤP: Bắt buộc check tick chọn Start in test mode (Sẽ có dòng cảnh báo màu cam hiện lên). Nhấn Enable. Thao tác này sẽ tự động nạp đoạn rule .read: true, .write: true vào tường lửa của Database.
  5. Vào Project Settings (Icon Bánh răng) tìm lấy dải mật mã Web API Key. Copy Ghi chú ra file Notepad.
  6. Quay lại giao diện Realtime Database, copy dải Database URL. (Nhớ nguyên tắc xóa dấu xuyệt `/` ở cuối). Ghi chú ra Notepad.

2 Pha 2: Kiến tạo Dữ liệu Mẫu (JSON Tree Initialization)

Mục đích: Mồi sẵn một biến trạng thái đèn trên cấu trúc Web để con chip ESP8266 có mục tiêu trỏ tới để đọc (Get) khi boot lên.

  1. Ngay giữa màn hình Realtime Database (Tab Data), rê chuột vào cuối đoạn link gốc trên cùng sẽ thấy một dấu Cộng (+) mờ mờ hiện ra. Bấm vào dấu + đó.
  2. Ô Name (Đại diện cho Key): Gõ chữ Den_D6.
  3. Ô Value (Đại diện cho Giá trị): Gõ số 0. Lưu ý sinh tử: Gõ số 0 trần trụi, tuyệt đối không gõ chữ "0" có chứa dấu ngoặc kép hay kèm khoảng trắng. Firebase phân biệt ép kiểu cực kỳ khắt khe.
  4. Nhấn nút Add. Bạn vừa tạo xong 1 Nhánh Dữ liệu (Data Node) đầu đời. Dữ liệu số nguyên sẽ hiển thị highlight màu Xanh Lục/Cam.

3 Pha 3: Biên dịch Não bộ Nhúng IoT (Firmware Flashing)

Mục đích: Tích hợp thư viện lõi của Mobizt và đẩy mã nguồn C++ đồng bộ xuống Vi điều khiển.

  1. Mở phần mềm Arduino IDE. Kiểm tra kỹ Library Manager xem thư viện Firebase Arduino Client... của Mobizt đã hiện chữ INSTALLED chưa.
  2. Sao chép toàn bộ Mã nguồn Học thuật Fail-safe ở Phần 13 dán vào IDE.
  3. Thử Thách Vượt Bẫy: Cập nhật cẩn thận thông số WiFi, tìm và tự tay thay thế các đoạn <...> bằng API_KEY và DATABASE_URL thực tế của bạn. Đảm bảo code sạch sẽ, không dư ngoặc nhọn.
  4. Nhấn Upload. Upload xong mở ngay Serial Monitor (Baudrate 115200). Đè nút RST cứng trên board để reset mạch từ đầu. Chờ xem Board lấy được chữ ký Xác thực Token (Anonymous Auth) thành công không.

4 Pha 4: Thẩm định Đồng bộ Đám mây (Cloud Data Sync Testing)

Mục đích: Chứng minh giao thức Read (Kéo về) và Write (Đẩy lên) hoạt động ổn định xuyên quốc gia.

  1. Nghiệm thu Luồng Write (Uplink: ESP ➔ Cloud): Xếp cửa sổ Serial Monitor và cửa sổ Trình duyệt Web Firebase song song kế bên nhau. Cứ đúng 10 giây (theo Timer định thời C++), trên Serial sẽ báo [SYNC OK]. Lập tức nhìn sang Web Firebase, các Node /NhietDo và /DoAm sẽ tự động chớp nháy highlight báo hiệu số liệu mới vừa bị ghi đè. Áp tay vào cảm biến DHT11, chờ 10s để thấy thông số trên web nảy vọt lên.
  2. Nghiệm thu Luồng Read (Downlink: Cloud ➔ ESP): Trên trang Web Firebase, đưa chuột bấm đúp trực tiếp vào con số 0 của Node Den_D6. Sửa nó thành số 1, gõ phím Enter. Ngay lập tức, đèn LED D6 trên phần cứng SÁNG RỰC LÊN! Đổi số 1 thành 0 lại trên Web, đèn tắt ngóm. Bạn đã thao túng thành công hệ thống Đám mây NoSQL của Google!

⚠️ 11. Trạm Kiểm Tra Kiến Thức (Interactive Q&A)

Chứng minh Khả năng Tư duy CSDL Đám mây (Cloud Database Architect):

Sinh viên hãy suy luận và trả lời các câu hỏi sau trước khi đi vào mã nguồn thực tế:

1. Khác biệt cốt lõi giữa "API Key" và "Security Rules" trong bảo mật Firebase là gì?
💡 Gợi ý tư duy: API Key chỉ giống như "Biển số nhà", nó giúp thiết bị biết dự án nằm ở đâu trên mạng. Nó hoàn toàn không có khả năng bảo mật nội dung bên trong. Security Rules mới chính là ổ khóa thực sự, quyết định ai (người dùng nào, email nào) mới có quyền được phép Đọc hoặc Ghi dữ liệu vào hệ thống.
2. Dấu gạch chéo / trong đường dẫn "/TramQuanTrac/Den_D6" mang ý nghĩa gì?
💡 Gợi ý tư duy: Khác với CSDL SQL truyền thống dùng Bảng (Table), Firebase là CSDL NoSQL lưu dữ liệu dưới dạng cây phân cấp (JSON Tree). Dấu gạch chéo / mô phỏng đường dẫn thư mục, chỉ ra rằng Den_D6 là một Nhánh con (Node/Child) nằm bên trong thư mục gốc là TramQuanTrac.
3. Bài toán Type Mismatch: Nếu bạn cố tình gõ chữ "1" (String) lên Web thay vì gõ số 1 (Int), mạch phản ứng ra sao?
💡 Gợi ý tư duy: Hệ thống C++ định kiểu tĩnh cực kỳ khắt khe. Nếu Code dùng hàm fbdo.getInt() để yêu cầu Số nguyên, nhưng Firebase lại trả về Chuỗi văn bản, quá trình ép kiểu sẽ thất bại. Mạch vi điều khiển sẽ không chớp đèn và bỏ qua lệnh này, có thể ném ra một thông báo lỗi ở Serial.
4. Tại sao khái niệm "Real-time" trong Firebase lại khác với "Hard Real-time" trong máy công nghiệp?
💡 Gợi ý tư duy: "Real-time" ở Firebase mang ý nghĩa "Đồng bộ gần thời gian thực (Near Real-time)". Dữ liệu được đẩy qua WebSockets lên mây và phổ biến xuống các thiết bị trong vòng vài phần mười giây. Nó có thể bị trễ do nghẽn mạng Internet. Khác hoàn toàn với "Hệ thời gian thực cứng" (Deterministic) trong tự động hóa, nơi sự chậm trễ 1 mili-giây có thể gây thảm họa vật lý.

Lúc nhập liệu lỡ tay gõ khoảng trắng hoặc chữ. C++ đọc bằng hàm getInt() "nhai" không được chuỗi String sẽ báo lỗi tịt ngòi. #include <ESP8266WiFi.h>
#include <Firebase_ESP_Client.h> // Thư viện lõi Mobizt (Bắt buộc phải cài qua Library Manager)
#include "DHT.h"

// Cung cấp cỗ máy chạy ngầm tự động gia hạn Token Auth để mạch không bị rớt mạng sau 1 tiếng
#include "addons/TokenHelper.h"
// Cung cấp các hàm in xuất Payload hỗ trợ xử lý luồng dữ liệu RTDB
#include "addons/RTDBHelper.h"

/* ======================================================================
   KHỐI 1: CẤU HÌNH MẠNG VÀ KREDENTIAL FIREBASE (BẮT BUỘC ĐIỀN)
   ====================================================================== */
#define WIFI_SSID "<NHẬP_TÊN_WIFI_CỦA_BẠN>"
#define WIFI_PASSWORD "<NHẬP_MẬT_KHẨU_WIFI>"

// Lấy từ Firebase Console -> Project Settings -> General -> Web API Key
#define API_KEY "<NHẬP_CHUỖI_API_KEY_BẮT_ĐẦU_BẰNG_CHỮ_AIzaSy_VÀO_ĐÂY>"

// Lấy từ Realtime Database. QUY TẮC THÉP: XÓA BỎ DẤU GẠCH CHÉO (/) Ở ĐUÔI CÙNG
#define DATABASE_URL "<NHẬP_URL_DATABASE_CỦA_BẠN_VÀO_ĐÂY>" 

/* ======================================================================
   KHỐI 2: CẤU HÌNH KIẾN TRÚC PHẦN CỨNG
   ====================================================================== */
#define DHTPIN 14        // Nối dây cáp Data DHT11 vào lỗ D5 (Tương ứng GPIO14)
#define DHTTYPE DHT11
DHT dht(DHTPIN, DHTTYPE);

#define LED_PIN 12       // Nối Đèn LED vào lỗ D6 (Tương ứng GPIO12)

/* ======================================================================
   KHỐI 3: KHỞI TẠO CÁC ĐỐI TƯỢNG HẠ TẦNG FIREBASE
   ====================================================================== */
FirebaseData fbdo;       // Đối tượng "Xe tải chở Hàng" (Chứa Request/Response Payload từ Cloud)
FirebaseAuth auth;       // Đối tượng Xác thực (Chứa Thông tin Chứng minh thư Đăng nhập)
FirebaseConfig config;   // Đối tượng Cấu hình (Chứa URL, API Key để định tuyến tìm máy chủ)

// Biến đếm thời gian (Đồng hồ cát) cho thuật toán Đa nhiệm Non-blocking (Timer)
unsigned long sendDataPrevMillis = 0; 
unsigned long getLedPrevMillis = 0;

bool signupOK = false;   // Cờ trạng thái đánh dấu việc đăng ký lấy Token thành công hay chưa

void setup() {
  Serial.begin(115200);
  dht.begin();
  pinMode(LED_PIN, OUTPUT);
  digitalWrite(LED_PIN, LOW); // Ghìm phần cứng tắt đèn an toàn khi vừa boot lên

  // --- KẾT NỐI WIFI ---
  WiFi.begin(WIFI_SSID, WIFI_PASSWORD);
  Serial.print("\n>> Đang đàm phán xin IP từ Wi-Fi");
  while (WiFi.status() != WL_CONNECTED) {
    Serial.print(".");
    delay(300);
  }
  Serial.println("\n>> Đã vào mạng nội bộ. IP Cục Bộ của bạn là: " + WiFi.localIP().toString());

  // --- KHỞI TẠO LÕI MÁY TRẠM FIREBASE ---
  Serial.printf(">> Đang nạp Firebase Client Version v%s\n", FIREBASE_CLIENT_VERSION);
  config.api_key = API_KEY;
  config.database_url = DATABASE_URL;

  // Thuật toán Xác thực Ẩn danh (Anonymous Auth):
  // Dù Database đang tạm mở bằng Test Mode, các thư viện hiện đại của Google vẫn ép ESP8266
  // phải có 1 mã định danh (Token) để bảo vệ hạ tầng, tránh bị hệ thống Anti-Spam (DDOS) chặn lại.
  if (Firebase.signUp(&config, &auth, "", "")) {
    Serial.println(">> Đăng ký Lấy Token Ẩn danh thành công! Đã thông chốt Tường lửa Firewall.");
    signupOK = true;
  } else {
    Serial.printf(">> [CẢNH BÁO LỖI] Lấy Token thất bại: %s\n", config.signer.signupError.message.c_str());
  }

  // Khai báo gán hàm callback xử lý việc cấp lại Token ngầm khi Token cũ hết hạn (Mỗi 60 phút)
  config.token_status_callback = tokenStatusCallback; 

  // Khởi động Dịch vụ (Service) Firebase chạy ngầm song song cùng Hệ điều hành RTOS
  Firebase.begin(&config, &auth);
  Firebase.reconnectWiFi(true); // Bật tính năng Tự động phục hồi kết nối nếu Router rớt WiFi giữa chừng
}

void loop() {
  unsigned long currentMillis = millis(); // Nhìn lên đồng hồ hệ thống xem đã trôi qua bao nhiêu mili-giây

  /* ======================================================================
     TÁC VỤ 1: ĐỌC DỮ LIỆU TỪ FIREBASE (PULL - LẤY LỆNH ĐIỀU KHIỂN XUỐNG)
     Bản chất: Hàm getInt() chạy định kỳ để quét sự thay đổi của Node /Den_D6 trên mây
     ====================================================================== */
  // Chỉ mạnh dạn hỏi Firebase nếu API Token đã được cấp phát (Ready) 
  // Và khoảng cách giữa các lần hỏi tối thiểu là 1000ms (1s) để tránh sập máy chủ.
  if (Firebase.ready() && signupOK && (currentMillis - getLedPrevMillis > 1000 || getLedPrevMillis == 0)) {
    getLedPrevMillis = currentMillis; // Reset lại đồng hồ đếm lùi nhánh Get
    
    // Gửi gói Request: "Xin chào Google, cho tôi xin giá trị Số nguyên (Int) tại Node /Den_D6"
    if (Firebase.RTDB.getInt(&fbdo, "/Den_D6")) {
      
      // KỸ THUẬT PHÒNG THỦ: Nếu Cloud đồng ý, hàm dataType() sẽ soi xem số liệu kéo về có đúng chuẩn là số (int) không
      // Phòng trường hợp User nhập bậy bạ chữ Text trên Web làm treo mạch.
      if (fbdo.dataType() == "int") {
        
        int ledCommand = fbdo.intData(); // Mở thùng xe fbdo lấy cục con số ra
        
        // Điều hướng Logic chốt Phần cứng
        if (ledCommand == 1) {
          digitalWrite(LED_PIN, HIGH);
        } else {
          digitalWrite(LED_PIN, LOW);
        }
      }
    } else {
      // Bẫy lỗi Debug: Có thể Link URL sai, Data Mismatch (Bắt int nhưng Firebase trả String), hoặc rớt mạng
      Serial.println("[LỖI GET] Kéo biến Đèn thất bại: " + fbdo.errorReason());
    }
  }

  /* ======================================================================
     TÁC VỤ 2: GHI DỮ LIỆU LÊN FIREBASE (PUSH - BÁO CÁO CẢM BIẾN VIỄN TRẮC)
     Luật bảo vệ máy chủ: Chỉ được phép báo cáo cập nhật nhiệt độ 10 giây (10000ms) 1 lần
     ====================================================================== */
  if (Firebase.ready() && signupOK && (currentMillis - sendDataPrevMillis > 10000 || sendDataPrevMillis == 0)) {
    sendDataPrevMillis = currentMillis; // Reset lại đồng hồ đếm lùi nhánh Set

    float t = dht.readTemperature();
    float h = dht.readHumidity();

    // Khắc phục ngoại lệ (Exception) của Phần cứng Hardware
    if (isnan(t) || isnan(h)) {
      Serial.println("[LỖI HARDWARE] Cảm biến DHT11 không phản hồi!");
      return; // Dừng lại tại đây, tuyệt đối không đẩy rác (NaN) lên mây làm bẩn Database
    }

    // 1. Ghi đè (Set Float) thông số Nhiệt độ vào nhánh Cây có tên "/NhietDo"
    if (Firebase.RTDB.setFloat(&fbdo, "/NhietDo", t)) {
      Serial.print(">> [SYNC OK] Đã tải lên Đám mây Nhiệt Độ: ");
      Serial.println(t);
    } else {
      Serial.println(">> [LỖI SET] Lưu Nhiệt độ thất bại: " + fbdo.errorReason());
    }

    // 2. Ghi đè (Set Float) thông số Độ ẩm vào nhánh Cây có tên "/DoAm"
    if (Firebase.RTDB.setFloat(&fbdo, "/DoAm", h)) {
      Serial.print(">> [SYNC OK] Đã tải lên Đám mây Độ Ẩm: ");
      Serial.println(h);
    } else {
      Serial.println(">> [LỖI SET] Lưu Độ ẩm thất bại: " + fbdo.errorReason());
    }
  }
}

Nhiệm vụ 1: Triển khai Cảm biến An ninh (Sensor ➔ Push ➔ Cloud Data) Lấy 1 Nút nhấn (Push Button) hoặc Công tắc từ (Magnetic Switch) kèm điện trở kéo xuống (Pull-down) 10k cắm vào lỗ chân D7 của mạch (Kế thừa hoàn toàn phần cứng Lab 2). Hãy giả lập cái nút nhấn cơ học này là một Cảm biến Cảnh báo Mở Cửa nhà kho. Hãy lập trình bổ sung khối C++: Bất cứ khi nào trạng thái cửa thay đổi (Bị Mở ra hoặc Đóng lại đột ngột), ESP8266 sẽ lập tức bắt sườn và ném lệnh setInt ghi giá trị (1 hoặc 0) lên một Nhánh Cây hoàn toàn mới trên Đám mây có tên là /TrangThaiCua. Giám sát màn hình máy tính Firebase xem thông số có nảy Live hay không.
Nhiệm vụ 2: Mở cánh cửa Trở thành Full-stack Web Developer (Đề tài Lớn) Vi mạch NodeMCU của bạn đã hoàn thành xuất sắc vai trò làm "Công nhân" đẩy Data lên Cloud. Giờ là lúc tạo một Giao diện Dashboard để "Hưởng thụ" Data đó ở Tầng Ứng dụng. Trên Laptop máy tính, hãy mở phần mềm Notepad hoặc VS Code tạo một file rỗng index.html. Sử dụng thẻ Script để nhúng thư viện Firebase JavaScript SDK (CDN) vào. Lập trình 1 đoạn hàm JS thuần chọc vào đúng cái DATABASE_URL, kéo giá trị Nhiệt độ trên mây về và vẽ hiển thị ra một thẻ HTML <h1> khổng lồ giữa màn hình Laptop. Trải nghiệm này kết nối hoàn hảo Môn Nhúng và Môn Lập trình Web! Chúc mừng, bạn đã tạo ra ứng dụng Web Serverless (Không phụ thuộc máy chủ Local) đầu tiên!

👨‍🏫 17. Lời nhắn nhủ từ Mentor trước giờ thực chiến

Khai mở Tư duy Hệ Quản Trị Đám Mây NoSQL:
  • Chuyển đổi Mô hình (Paradigm Shift): Ở Lab 6 (Local Server), nếu cúp điện là bay biến sạch data. Ở Lab 5 (Telegram) các em gửi tin nhắn xong nó không lưu theo cấu trúc CSDL để sau này vẽ biểu đồ được. Hôm nay, Lab 7 đưa các em chạm tới đỉnh chóp của Kiến trúc Dữ liệu: Dữ liệu Cảm biến sẽ được lưu trữ Bền vững (Persistence) trên hệ thống máy chủ CSDL của Google. Đây là Cột Sống hạ tầng của mọi siêu ứng dụng phần mềm. Sau khi thông suốt cấu trúc Cây JSON này, việc giao data cho đội phần mềm viết App Mobile vẽ Biểu đồ sẽ dễ như trở bàn tay!
  • Giăng Cạm bẫy Bức tường Lửa (Test Mode Trap): Hơn 90% sinh viên khi tạo Project sẽ mải miết bấm Next liên tục mà quên gạt chọn sang Test mode. Kết quả tất yếu: Mạch Boot lên ném ra dòng lỗi đỏ màn hình Serial vì Permission denied (401). Đây là một bài học đắt giá! Việc Google từ chối là họ đang làm đúng để bảo vệ em. Đây là phương pháp sư phạm thực chứng tốt nhất để tạc dạ khái niệm Tường lửa Phân quyền (Firewall Authentication) trong CSDL. Nhớ kỹ: Test Mode chỉ dùng trong Lab, nghiêm cấm dùng trong đồ án thực tế mang ra doanh nghiệp!
  • Điều trị Căn bệnh "Type Mismatch" (Xung đột kiểu dữ liệu): Tại Pha 4 kiểm thử, khi phải gõ số 1 vào giao diện Firebase để bật đèn, sinh viên rất hay bấm dư một dấu cách (Space) hoặc gõ chữ "1" có ngoặc kép. Hàm getInt() của C++ "ăn" phải Chuỗi String sẽ nôn ra giá trị Fail rác (0). Mạch liệt hoàn toàn. Mẹo Nhãn khoa Kỹ thuật: "Trong Firebase, Số thực (Int/Float) luôn tự hiển thị MÀU XANH LỤC/CAM, còn Chuỗi văn bản (String) hiện MÀU ĐỎ. Hãy gõ làm sao cho nó ra con số màu Xanh thì code mới chạy!".
  • Nghiệm thu Đỉnh cao (Zero Touch Sync Test): Để lấy điểm A tuyệt đối, em hãy gấp Laptop lại (Không nhìn Log Serial). Dùng 1 tay áp chặt lên cảm biến DHT11 truyền nhiệt, mắt nhìn thẳng lên Cây dữ liệu JSON trên trình duyệt Web Firebase. Khi nhiệt độ lòng bàn tay thẩm thấu làm biến đổi cảm biến, khu vực Nhánh /NhietDo trên màn hình phải tự động tóe lên màu cam chớp nháy báo hiệu Data vừa bị Ghi đè Live. Sinh viên vượt ải Tốt nghiệp Lab 7 thành công rực rỡ!
